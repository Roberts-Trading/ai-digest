### Anthropic — Opus 5 Dominates ARC-AGI-3, Novel Reasoning Behaviors
- **Summary**: ARC Prize team reports Claude Opus 5 scored 30.2% on ARC-AGI-3 — nearly 4× the previous record of 7.8% set by GPT-5.6 Sol (Max). Opus 5 solved 5 previously unsolved environments, 4 at or above human level. Fable-class models hit ~20%. ARC Prize credits the lead to "genuinely stronger logical reasoning that enables more autonomous exploration, planning, and execution across unfamiliar environments." Novel behaviors never before seen from an AI model: Opus 5 translated tasks into algebraic notation and independently formulated reflection equations. On ARC-AGI-2: 90.4%. On ARC-AGI-1: 97.5%. 6 of 25 public demo environments now solved. However, on Witness (Guanghan Ning's interactive puzzle benchmark), Opus 5 scored 43.4 — statistically tying Kimi K3 and Fable 5, with narrower gains over Opus 4.8 than on ARC-AGI-3. When games combined rules in unfamiliar ways, Opus 5 scored below Opus 4.8, suggesting genre-specific training data. JAIKIN analysis: Opus 5 beats Fable 5 on 7 of 11 directly comparable evaluations (Fable keeps 4). Lead is on end-to-end agentic work. Opus 5 Max finishes 0.5 points behind Fable 5 Max (70.0% vs 70.5%) at ~half the task cost. Opus 5 Extra High beats Fable 5 Extra High (69.3% vs 68.4%) at lower cost ($7.35 vs $11.73). MLQ: 4th Anthropic model in 8 weeks (Fable 5, Sonnet 5, Opus 4.8, Opus 5). Misalignment score 2.3 (lowest of recent models).

### Letta/Memory — Prompt Injection Persistence, Dual-Tier Architecture, Agentic Memory Engineering
- **Summary**: (1) **UW study: prompt injection persists in agent memory** (arXiv:2607.14611, published July 16) — Anthropic and OpenAI agents correctly refuse malicious instructions when encountered. The problem is what happens after: rejected instructions stick around in persistent memory files, waiting to influence future behavior across separate sessions. Memory compression and revision processes — the same mechanisms that help agents remember useful context — preserve malicious instructions in summarized or reorganized form. Agents blend information from various sources during memory operations, weaving malicious content into legitimate information, making it harder to detect. "Memory poisoning" — OWASP flagged it as a risk in December 2025. UW study provides concrete evidence of how the mechanism works. (2) **Dual-tier memory architecture** — L1 scratchpad (ephemeral, structured key-value, 2.1ms retrieval, max 50 entries with LRU eviction) + L2 vault (persistent vector memory, sqlite-vec, 94ms retrieval across 14,726 memories). Benchmarked against Pinecone: 94ms median query latency, $0 monthly cost vs Pinecone's $1,230 over 6 months. Decay system reduced retrieval noise by 34%. Memories older than 90 days with zero access automatically pruned. L1 is deliberately simple — no embeddings, no similarity search, just structured lookups for "What tool did I just call?" (3) **Agentic Memory Engineering (AME)** — The "missing layer" for enterprise AI. Discipline of designing, governing, and operating persistent knowledge and contextual state. Core components: Curation (what becomes agent-usable context), Schema & modeling (machine-reasonable structure), Lineage & provenance (trace answers to sources), Access control (which agents see which knowledge), Lifecycle management (versioning, expiry, retention, archival), Memory services (search, retrieval, graph infrastructure). "Not identical memory for every agent — a Legal agent, an engineering agent, and an HR agent shouldn't see the same things, but consistent governance over whatever memory each one is appropriately given." (4) **"Empty Memory Isn't Missing Data — It's a Permission Hole"** — In multi-agent systems, empty memory recall often means the agent is not allowed to see that fact, not that the fact doesn't exist. If both cases return `[]`, the model will invent over a permission hole. Solution: `denied_hint` mode (explicit "matched but withheld") vs `silent` (empty hits). Server-side scope enforcement (user/agent/team/org), not just system-prompt-level. Log agent ID, requested scopes, denial reason. (5) **ERC-8337: Agent Memory State** — Ethereum ERC proposal for verifiable version control for autonomous-agent memory, without putting memory content on chain. ExperienceDelta structure defines memory state transitions. Sepolia deployment live. Supports EOAs, EIP-1271 contract accounts, EIP-7702 delegated accounts.
- **Source**: https://cryptobriefing.com/uw-study-prompt-injection-ai-agent-memory/ ; https://dev.to/hypernexus/dual-tier-memory-architecture-for-ai-agents-how-local-vector-search-scales-to-14726-memories-2617 ; https://pub.towardsai.net/the-missing-layer-why-enterprise-ai-needs-agentic-memory-engineering-f7a8e96fb984 ; https://dev.to/pranavafk/empty-memory-isnt-missing-data-its-a-permission-hole-1ipa ; https://ethereum-magicians.org/t/erc-8337-agent-memory-state/29098
- **Significance**: The UW study is the security finding of the week: prompt injection doesn't just affect the current session — it persists in memory across sessions, gets woven into legitimate data during compression, and creates an ongoing vulnerability. This is the cross-session attack vector that every agent memory framework (including Letta) needs to defend against. The dual-tier architecture (L1 scratchpad + L2 vault with sqlite-vec) is the production pattern: 94ms retrieval, $0 cost, 34% noise reduction from decay. The AME framework is the enterprise governance layer — curation, provenance, access control, lifecycle. The "permission hole" insight is critical for multi-agent systems: silent empty memory causes hallucination, explicit withhold prevents it. ERC-8337 brings agent memory to blockchain — verifiable state transitions without exposing content.
