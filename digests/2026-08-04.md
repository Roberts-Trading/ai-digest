### Anthropic — Opus 5 Deep Dive: 80% System Prompt Removal, Beats Fable 5 at Half Price, Deliberately Lags Mythos 5 in Bio/Cyber for Safety
- **Summary**: (1) **Opus 5 performance deep dive** (DEV Community, Terabox) — Released July 24, 2026. Same price as Opus 4.8 ($5/M input, $25/M output) — half of Fable 5. Frontier-Bench v0.1: >2x Opus 4.8, surpasses every other model. CursorBench 3.2 (max effort): within 0.5% of Fable 5's peak, at half cost. Zapier AutomationBench: ~1.5x pass rate of next-best model. ARC-AGI 3: 3x next-best score (8% → 30% — leaderboard scales had to be recalculated). GDP Val: +100 points. Agentic terminal coding: 33% → 43%. Safety classifiers 85% less aggressive than previous versions. Default on Claude Max, strongest on Claude Pro. Model string: `claude-opus-5`. (2) **80% system prompt removal** (36Kr) — Boris Cherny (Anthropic engineer, Claude Code core developer) revealed they removed 80% of Claude Code's system prompts for Opus 5. The model did not become less capable — it grew more powerful. Tasks that previously required hand-holding no longer need explicit instruction. "Prompt engineering may no longer exist." Test: gave buggy code without telling the model there were bugs. Both GPT-5.6 and Opus 5 found all 6 bugs. Opus 5 found one extra (floating-point fee calculation when multiple products are added together). Opus 5 ran through the entire project on its own, put itself in the position of a product manager, analyzed the problem, and thought one step further about future issues. Used more efficient batch unpacking (struct.unpack vs GPT-5.6's sequential struct.unpack_from). "More product-oriented, flexible problem-solving." (3) **Deliberate safety lag** (TopCC) — Opus 5 deliberately does NOT push frontier in risky capabilities. Lags behind Mythos 5 in biology research and offensive cybersecurity. This is a deliberate design decision to ensure safe and aligned use. Safeguards allow beneficial use in cybersecurity and biology while striking a balance.

### Letta/Memory — Sleep-time Compute (Letta + UC Berkeley), Letta vs Mem0 Benchmark Controversy, Memory Governance as Control Plane
- **Summary**: (1) **Sleep-time Compute** (36Kr, Letta + UC Berkeley) — Letta and UC Berkeley researchers propose "Sleep-time Compute" — agents think during idle periods (no user query). S(c) → c′ transformation: pre-process context during sleep time, rewriting context to be more useful for future queries. When query q arrives, use much smaller test-time budget: T_b(q, c′) → a where b << B. Up to 2.5x per-query cost reduction with 10 queries per context. Advantage grows as user questions become more predictable from context. Paper: "Sleep-time Compute: Beyond Inference Scaling at Test-time" (arxiv.org/pdf/2504.13171). GitHub: github.com/letta-ai/sleep-time-compute. Core insight: "AI systems have an unreleased paradigm shift — not just reasoning when prompted, but actively deepening understanding of the world and tasks during inactive periods." For stateful AI systems, sleep-time compute provides a new scaling path beyond test-time compute. (2) **Letta vs Mem0 benchmark controversy** (36Kr) — Sarah Wooders (Letta CTO) publicly accused Mem0 of fabricating benchmark results. Mem0 claimed to run MemGPT on LoCoMo benchmark, but Letta team "cannot find a way to feed LoCoMo data into MemGPT/Letta without massive code refactoring." Mem0 didn't respond to clarification requests or provide a modified MemGPT implementation. Letta's counter: storing conversation history in a plain file (no specialized memory tools) achieved 74.0% on LoCoMo — higher than Mem0's best graph memory version (68.5%). Used GPT-4o mini with minimal prompting. Agent self-regulates: search_files → iterate → answer_question. "For well-designed agents, even simple file system tools are sufficient." Letta recommends their own Letta Memory Benchmark for apples-to-apples comparison — evaluates memory management in dynamic contexts, not just retrieval. (3) **Memory governance as control plane** (HackerNoon) — "Memory governance is becoming the control plane for agentic AI." Reliability is no longer only about the model — it depends on how memory is handled: what gets reused, when it needs checking, when it should expire. Anthropic described this shift as "context engineering": curating and maintaining the right set of information. Larger context windows don't solve memory issues. Practical steps: write policies for memory, provenance tags, TTL rules, permission-aware retrieval, read/write audit logs. "Memory is not only for retrieval — it's for governance."
- **Source**: https://www.36kr.com/p/3261133086015618 ; https://36kr.com/p/3423823155252610 ; https://hackernoon.com/memory-governance-is-becoming-the-control-plane-for-agentic-ai
- **Significance**: Sleep-time Compute is the most important memory research today — it's a new scaling dimension beyond test-time compute. The idea that agents should think during idle periods (not just when prompted) is the paradigm shift for stateful AI systems. The 2.5x cost reduction with 10 queries per context is the economic signal. The Letta vs Mem0 controversy is the benchmark integrity story — Mem0 allegedly fabricated results by claiming to run MemGPT on LoCoMo without a viable implementation path. Letta's counter (74.0% with plain files vs Mem0's 68.5% with graph memory) is the "simple tools suffice" argument. The memory governance framing (context engineering > prompt engineering) is the architectural shift — reliability is a memory problem, not a model problem. This directly connects to Meta's dual-agent memory result from yesterday.
