### Letta/Memory — LinkedIn Cognitive Memory Agent (Episodic/Semantic/Procedural/Working), InjecMEM Attack on Agent Memory (76.6% Success, MemGPT Tested), AgentFlow Trainable Workflows, Self-Editing Memory Unpredictability
- **Summary**: (1) **LinkedIn's Cognitive Memory Agent for agentic personalization** (Stack Overflow, Archyde) — NEW, major. LinkedIn built a Cognitive Memory Agent (CMA) architecture for production features like AI Hiring Assistant. Introduced by Distinguished Engineer Karthik Ramgopal and Principal AI Researcher Praveen Bodigutla. CMA is a shared infrastructure layer between application agents and foundation models. Four memory tiers: Episodic (time-indexed interaction history), Semantic (structured knowledge, persistent facts, evolving preferences), Procedural (learned workflows, execution patterns), Working (short-term in-session context). Ingestion layer processes unstructured inputs, extracts signals, determines what to store. Moved off GraphRAG in favor of tree-structured memory for faster incremental updates — percolate changes down relevant branch instead of re-indexing entire memory. Retrieval/orchestration layer is a planner-synthesizer LLM that reasons over memory for complex queries. Latency budget: memory processing ~10-20% of overall response latency. Human validation loops in enterprise recruiting. Internal platform, not open-sourced. Community alternative: cognitive-memory-layer on PyPI. (2) **InjecMEM: planting persistent instructions in AI agent memory via single prompt** (AI Governance Institute, CSO Online) — NEW, major security. Researchers from Shanghai Jiao Tong University and Ant Group demonstrated InjecMEM: a single ordinary user interaction plants persistent hidden instructions in an agent's memory layer. 76.6% success rate against MemoryOS. Also tested against MemGPT framework. Unlike prompt injection (defeated when session ends), InjecMEM survives across sessions — compromised memory entry influences future conversations with different users/tasks. No read/edit access to memory store required — uses standard interaction channels. Once stored, injected record is treated as part of agent's memory and surfaced during future tasks. Experts: "Most defenses focus heavily on model input, while memory sits further down the application stack. Enterprises need to ask basic security questions around memory: who can write to it, what gets stored, how validated, whether the source is trusted." Memory should be treated as a security-sensitive boundary requiring validation, access controls, and poisoning detection. NIST AI RMF may update to address persistent memory threats. (3) **AgentFlow: when the agent's workflow learns** (Lambda blog) — NEW. ICLR 2026 oral paper (top 1.1% of submissions). Stanford, Texas A&M, UC San Diego, Lambda. Splits agent into four modules sharing evolving memory: planner, executor, verifier, generator. Planner is trainable. Flow-GRPO (flow-based group refined policy optimization): broadcasts end-of-task outcome back to every turn, turning long multi-turn problem into tractable single-turn updates. 7B open model with AgentFlow beats GPT-4o across 10 benchmarks (search, agentic reasoning, math, science). Gains: +14.9%, +14.0%, +14.5%, +4.1%. Training planner in-flow: +17.2%. Offline SFT: -19.0%. Same model, opposite outcomes. "Learning a better workflow can matter as much as scaling the model." Shift from prompt engineering to training the workflow itself. (4) **Self-editing memory unpredictability** (DevCornerTo) — NEW. Letta's self-editing memory can be unpredictable. When corrected, agent sometimes updates memory block, sometimes writes contradicting entry, once "consolidated" both into summary keeping the wrong one. Letta shipped Recovery-Bench benchmark in 2026 to measure recovery from corrupted states — "tells you the industry knows this is real." Recommendations: timestamp every memory entry, decay old/inaccurate data, separate observed facts from inferences, require more evidence before acting on inferred memory. Memory corrections should be destructive: overwrite old entries, log changes in audit trail. (5) **Multi-agent amnesia problem** (Empirical Blog) — NEW. Per-agent isolated context windows cause lossy handoffs. Anthropic's own subagent docs describe this as intentional (prevent context pollution). Empirical proposes shared memory layer: any agent can write, any agent can query, no orchestrator needs to predict what future agents need. Agent 1 records what it found; Agent 3 queries for what's relevant. Honest about limitations: "No published benchmarks measuring how much a shared memory layer actually improves multi-agent pipeline quality. The next step is run a real pipeline both ways and publish what actually changes." (6) **Letta filesystem agent, Mem0 comparison, hybrid retrieval** — continued from Aug 25, same stories.
