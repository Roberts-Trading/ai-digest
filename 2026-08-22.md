### Anthropic — Computer Use, Skills API, Files API GA + Browser Use Tool, Mythos 5 in Claude Security + $35M Defender Fund, Watermark Goes Further Than EU Requires (Users Canceling)
- **Summary**: (1) **Computer Use, Skills API, Files API now generally available** (Claude blog, The New Stack) — Anthropic announced GA for three production agent building blocks on the Claude Platform. Computer use: Claude can operate software by interacting with UI (clicks, typing, scrolling). Updated tool now takes several actions per turn instead of one per model call, reducing calls and time. Now eligible for HIPAA-regulated workloads under BAA. Browser use tool (new): gives Claude a structured view of web pages via accessibility tree, targeting elements by reference (e.g., ref_3) instead of guessing coordinates from screenshots. 27 browser operations exposed by default. Multi-action per turn sends several tool_use blocks together, lowering latency and cost. Token cost: default Browser Use toolset adds ~6,600 input tokens per request. Security: run browser in isolated container/VM with minimal access; disable JavaScript and file uploads unless needed. Skills API: upload and version custom skills (folders of instructions, scripts, templates) that Claude loads only when a task calls for it. Runs in Claude's code execution sandbox — nothing to host. Files API: upload documents once, reference by ID in later requests, download agent-created files. Automatic file expiration, 5x higher rate limits, 1 TB storage per org. Also available via Microsoft Foundry; computer use/browser use coming to Google Cloud Vertex AI. (2) **Claude Mythos 5 in Claude Security + $35M Defender Advantage Fund** (The New Stack, Bloomberg) — Anthropic brought its most powerful model (Mythos 5, previously held back from public release) into Claude Security, its enterprise vulnerability scanner. Mythos 5 now scans enterprise codebases and suggests fixes. Public beta for all Claude Enterprise users. Guardrails: users get findings/patches, not direct model access — Anthropic controls the harness. Expanding Cyber Verification Program (vetted defenders get safeguarded Mythos access). New Defender Advantage Fund (0xDAF): $35M in Claude credits to find and patch vulnerabilities in open source software. Working with cybersecurity partners to integrate Mythos 5 into defender products. Project Glasswing: Mythos access for US government partners protecting critical infrastructure. (3) **Watermark goes further than EU requires** (Business Insider) — BI review of the law, supported by AI/policy experts, suggests Anthropic's watermark approach may go beyond what the EU requires. EU AI Act Article 50(2) partially permits not marking outputs when editing doesn't substantially alter meaning. Anthropic applies watermark globally (no per-region controls), rolling out because it can't apply region-by-region. Watermark designed to remain detectable through translations, summaries, and extensively edited text. Can appear even when Claude only edited/proofread text (implying Claude authored it). Some users canceled subscriptions over it. (4) **Watermark leads paying users to cancel** (BetaNews) — Within two weeks of the Aug 2 watermark rollout, four paying subscribers canceled citing professional liability, client contract risk, and no opt-out. Dozens more posted on social media about dropping subscriptions. Watermark covers Claude Platform API, app, Claude Code, Cowork, Tag, and Claude via AWS/Google Cloud/Microsoft Foundry. No opt-out on any tier including enterprise. Anthropic says no observed increase in cancellations. ~300K business customers as of Sept 2025. Dario Amodei posted that the industry's central failing was not delivering promised benefits — concrete scientific results, not messaging, would rebuild trust.

### Letta/Memory — Agent Memory as Infrastructure (Tiered Architecture with Mem0/Letta), Omnigent + Hindsight Bridge, StateMemBench/StateMem (State Tracking), Memory API Throwing Away the Truth, Hindsight Academy Launched, ReFind #2 on Agent Memory Leaderboard
- **Summary**: (1) **Agent memory as infrastructure** (DEV Community) — A developer who ran AI agents in production for 6 months documents a tiered memory architecture after experimenting with Mem0, Letta, and custom implementations. Tier 1: Episodic (short-term, high-fidelity, vector store "episodes," text-embedding-3-small). Tier 2: Semantic (long-term, summarized, vector store "facts," confidence field: 1.0 for trusted/new facts, 0.7 for inferred/older — retrieval weights by confidence before passing context to LLM, solving the "equal authority" problem. Tier 3: Procedural (stable, versioned, DocumentStore "procedures," TTL and re-onboarding mechanism, last_validated timestamps, quarterly review). Last 50 episodes raw, older as summaries. Key shift: "agent memory as a feature" to "agent memory as infrastructure" — design from the start with explicit decisions about what gets remembered/discarded, authority per tier, conflict resolution. (2) **Omnigent + Hindsight bridge** (Fodev JEO) — Hindsight is Vectorize's open-source agent-memory system (MIT, ~20.7K stars) exposing three primitives: retain, recall, reflect. Registered as runner-local in omnigent's tool_dispatch.py — the runner intercepts tool calls before they reach the harness, executes locally against hindsight-client. The wrapped harness (Claude SDK, Codex, Cursor, Pi) never learns what memory is — it emits a tool call, the runner intercepts it, executes locally, hands back result. Memory survives swapping harnesses mid-project. Config: api_key, api_url, bank_id, budget, recall_tags_match. Ranges: low/mid/high budgets. Practical: use omnigent[hindsight], verify cross-session recall. (3) **StateMemBench / StateMem** (AI News Brief) — arXiv paper: existing memory benchmarks focus on recall, but effective memory must track evolving world state (facts, constraints, decisions revised over long interactions). StateMemBench: 234 multi-session scenarios, two conversation-length regimes. Closed-pool grading: current state vs. superseded state vs. fail. StateMem: state-first memory method, tracks supersession and relational dependencies. Results: +1.8x over strongest same-backbone baseline on DeepSeek-V4-Flash (0.205→0.363), +1.6x over strongest memory system on Qwen-3.5-9B (0.149→0.233), competitive with long-context. Lightweight single-call wrapper over existing systems: +32 to +67 points across six backends. +15 to +32 points attributed to state structure, not added context. (4) **Memory API throwing away the truth** (Mango Developer) — Storage layer has bitemporal modeling (validity windows, supersession), but the retrieval API returns flat ranked lists, discarding edges between records. Example: agent asks "what database does production use?" API returns PostgreSQL (0.94) and MongoDB (0.91). Agent picks PostgreSQL, but production migrated to MongoDB 4 months ago. The store knew the edge; the API threw it away. (5) **Memory API lying to your agent** (DEV Community, Ken Walger) — Memory APIs that return only content and similarity scores implicitly tell agents records are independent and ranking is the only relationship. Edges (supersession, provenance, authority, state) must be hydrated before ranking, not after — a pre-ranking allocation problem, not a post-filter. Current retrieval enhancements (embeddings, hybrid search, rerankers, metadata filters, graph retrieval, larger context) help find relevant info but don't address inter-record relationships. The API has become the lossy boundary. (6) **Hindsight Academy launched** (Hindsight/Vectorize) — Free, hands-on course to build memory-powered agents. Four courses, 20 lessons, ~1.3 hours. Interactive lessons with animated explainers and real retain/recall/reflect calls against live Hindsight instance. Progress dashboard, certificate per course. Course 3: Build a Memory-Powered Agent (intermediate, store/recall, user separation, memory freshness, MCP/LangGraph/CrewAI integration). Course 4: Take It to Production (advanced, Cloud/self-host, Docker/Kubernetes, model selection, monitoring/scaling, data migration). (7) **ReFind #2 on Agent Memory Leaderboard** (DEV Community) — ReFind keeps raw conversation logs and searches them when needed, rather than pre-building complex memory representations. Agent Memory Leaderboard (AML) Open: #2 among open-source memory systems, score 44.97. (8) **Agent harness context management as governance continued** (NHIMG/Arize) — Letta named alongside Pi, OpenClaw, Claude Code. Context management = identity governance. Inherited context = standing privilege. (9) **Letta-Code trending on GitHub continued** (StartupCorners) — letta-ai/letta-code (+16). (10) **Feedback dilemma continued** (DEV Community) — Letta exposes feedback on agent steps, not on memories. Practical lever: standing instructions in AGENTS.md/CLAUDE.md. (11) **bitdrift $15M seed continued** (Dealroom) — Mobile observability for AI agents, top 3% of US enterprise software seed deals. (12) **Russian article on Letta agents with memory and versioning via git** (vc.ru) — MemGPT creators' project: agents store context, identity, skills in memory blocks tracked via git, synced with GitHub. Agent rewrites system prompt as it learns. "Dreaming" mode periodically reorganizes context. CLI, desktop, browser, messengers (Telegram, Slack, Discord). Skills from ~/.letta (global), .agents/skills (project), MemFS (local). Subagents: general-purpose, forked, recall, history-analyzer. ## New Tools & Discoveries

### Claude Computer Use + Browser Use + Skills API + Files API (GA)
- **What it does**: Four production agent building blocks now GA on Claude Platform. Computer use: Claude operates software via UI interaction (clicks, typing, scrolling), multiple actions per turn. Browser use: Claude reads web pages via accessibility tree, targets elements by reference (ref_3) not screenshot coordinates, 27 browser operations. Skills API: upload/version custom skills (instructions, scripts, templates), loaded only when needed, run in Claude's sandbox. Files API: upload documents once, reference by ID, download agent-created files, auto-expiration, 5x rate limits, 1 TB/org. Also via Microsoft Foundry; computer use/browser use coming to Vertex AI.
- **Why notable**: Complete production agent toolkit — operate software, browse web with structured targeting, apply team expertise via skills, persist documents. Multi-action-per-turn reduces calls/cost. HIPAA eligibility. The browser accessibility-tree approach (vs. screenshot guessing) is the same pattern as OpenAI's computer use.

### Grok Build (xAI/SpaceXAI)
- **What it does**: Terminal-native CLI/TUI coding agent. Plan Mode: maps steps before touching files. Up to 8 specialized subagents in isolated Git worktrees. Integrates AGENTS.md, hooks, plugins, MCP servers. Fullscreen TUI + headless mode (-p) for CI/CD. Agent Client Protocol support. Open-sourced on GitHub. Backend: grok-build-0.1 / Grok 4.6, API for custom harnesses.
- **Why notable**: xAI's direct terminal-native competitor to Claude Code and Codex. Plan Mode before file changes, 8 parallel subagents, Git worktree isolation, headless mode for automation. Open-sourced. The first major coding agent from the SpaceXAI/Cursor combined entity.

### Hindsight (Vectorize) + Omnigent Bridge
- **What it does**: Hindsight is Vectorize's open-source agent-memory system (MIT, ~20.7K stars). Three primitives: retain, recall, reflect. Registered as runner-local in Omnigent's tool_dispatch.py — runner intercepts tool calls before harness, executes locally against hindsight-client. Memory survives swapping harnesses mid-project. Config: api_key, api_url, bank_id, budget, recall_tags_match. Ranges: low/mid/high budgets.
- **Why notable**: Cross-harness memory persistence — the runner-local bridge means memory is not stored inside the tool/harness but intercepted and executed locally. Memory survives swapping Claude Code → Codex mid-project. The ~20.7K stars signal strong community adoption.

### StateMem / StateMemBench
- **What it does**: StateMem is a state-first memory method that explicitly tracks supersession and relational dependencies. StateMemBench is a benchmark of 234 multi-session scenarios across two conversation-length regimes, grading whether answers reflect current state, superseded state, or fail.
- **Why notable**: Addresses the evolving-state gap in memory benchmarks. +1.8x over strongest same-backbone baseline (DeepSeek-V4-Flash), +1.6x over strongest memory system (Qwen-3.5-9B). Lightweight single-call wrapper over existing systems: +32 to +67 points across six backends. +15 to +32 points attributed to state structure, not added context.
